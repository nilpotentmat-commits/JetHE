This maps the 61 entries in `theory/supplementary-inventory.json` into the supplied artifact. The supplementary archive currently contains 792 selected original source/data files. All archive hashes and all listed target paths were checked; no archived experiment or HE workload was run for this mapping.

This ledger resolves source references. It does not claim that every proof or experiment in the 158-page supplement has a runnable reproduction. A mapped directory contains selected descendants; it is not a claim that the original directory, machine environment, dependency closure or campaign has been copied in full.

## Status meanings

- **portable** (15 entries): A named finite checker, selected implementation or portable launcher is supplied. This does not make every program in the historical source directory portable or prove a theorem.
- **archival** (39 entries): Original source/data or verified identical bytes are supplied for inspection. Archival entry points are not claimed runnable and records are not new experiments.
- **external** (4 entries): The reference is to a separately acquired dependency source/revision. Build instructions may be supplied, but those instructions are not the referenced dependency source.
- **generated** (3 entries): The reference denotes historical environment-specific build material intentionally omitted. A supplied recipe can create a new build; it does not recreate historical bytes.
- **unresolved** (0 entries): No unambiguous artifact target has been established. Absence of this status does not imply full supplementary reproducibility.

An entry is marked portable when it has a specifically identified portable implementation or finite checker, even if additional historical files remain archival. The JSON distinguishes every target and gives full member lists for directory/pattern matches. No whole-theorem or whole-campaign coverage is implied by the portable status.
